# Rhythm Axis 模块完整架构分析

## 一、各类职责和核心功能

### 1. RhythmAxisModule（主模块/协调者）

**职责**：作为整个节奏轴系统的协调者和入口点。

**核心功能**：
- 初始化所有子组件（emitter、hit_zone、beat_generator、effect_manager、axis_logic）
- 加载配置文件（rhythm_axis_config.tres、rhythm_effect_config.tres）
- 管理运行状态（_is_running）
- 处理事件订阅和分发
- 创建可视化节点（Line2D轴线、ColorRect判定区）
- 每帧更新块的可视化位置

**公共接口**：
```gdscript
func initialize() -> void           # 初始化所有组件
func start() -> void                 # 启动节奏轴
func stop() -> void                  # 停止并清理
func cleanup() -> void               # 完全清理资源
func get_effect_manager() -> Node     # 获取特效管理器
```

**默认配置**：
| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| bpm | 120.0 | 节拍速度 |
| slide_duration | 1.5 | 块滑动时长（秒） |
| axis_length | 800.0 | 轴长度 |
| axis_y | 300.0 | 轴Y坐标 |
| hit_zone_x | 700.0 | 判定区X坐标 |
| block_size | 40.0 | 块大小 |
| judge_perfect_window | 0.08s | Perfect 判定窗口 (±80ms) |
| judge_good_window | 0.18s | Good 判定窗口 (±180ms) |
| judge_miss_after | 0.3s | Miss 超时时间 (300ms) |

---

### 2. BeatGenerator（节拍生成器）

**职责**：按固定BPM发送节奏事件，是整个系统的"心跳"。

**核心功能**：
- 根据BPM计算节拍间隔（60.0 / BPM）
- 使用Timer定时触发节拍
- 通过BeatStrategy计算每拍的强度/类型
- 发送`rhythm:beat`事件

```gdscript
func _update_timer_interval() -> void:
    # BPM 转间隔：60 / BPM = 每拍的秒数
    var interval: float = 60.0 / _bpm
    _beat_timer.wait_time = interval
```

**公共接口**：
```gdscript
func initialize() -> void            # 初始化
func start() -> void                  # 启动定时器
func stop() -> void                   # 停止定时器
func reset_strategy() -> void          # 重置节拍策略
func cleanup() -> void                 # 清理资源
func set_bpm(new_bpm: float) -> void  # 设置 BPM
func get_bpm() -> float               # 获取当前 BPM
```

---

### 3. BeatStrategy（节拍策略基类）

**职责**：定义节拍算法的接口规范。

**核心功能**：
- 抽象方法：`get_beat_data()` 返回当前节拍数据
- 抽象方法：`advance_beat()` 推进到下一拍
- 抽象方法：`reset()` 重置计数器

**实现类 LinearBeatStrategy**：
- 每拍强度相同
- 第一拍为"downbeat"（力度稍强：1.2），其他为"normal"（1.0）
- 支持每小节拍数配置（默认4/4拍）

### 4. RhythmEmitter（发射器）

**职责**：在每个节拍点创建并发射音乐块。

**核心功能**：
- 生成唯一的block_id
- 计算发射时间和目标到达时间
- 发送`rhythm:block_emitted`事件

```gdscript
var emit_time: float = Time.get_ticks_msec() / 1000.0
var hit_target_time: float = emit_time + _slide_duration
var block_data := {
    "block_id": block_id,
    "emit_time": emit_time,
    "hit_target_time": hit_target_time,
    "slide_duration": _slide_duration
}
EventBus.fire("rhythm:block_emitted", block_data)
```

**公共接口**：
```gdscript
func start() -> void                             # 启动，重置计数器
func stop() -> void                              # 停止
func set_bpm(bpm: float) -> void                # 设置 BPM
func set_slide_duration(seconds: float) -> void # 设置滑动时长
func emit_block() -> Dictionary                  # 发射一个块
```

### 5. RhythmAxisLogic（轴逻辑）

**职责**：管理所有滑动中的音乐块，推进进度，通过事件通知块已到达判定区。

**核心功能**：
- 维护`_sliding_blocks`列表（未判定的块）
- 每帧更新所有块的进度
- 块到达判定区时**通过事件通知**（不再直接调用 HitZone）
- Miss 检查也**通过事件通知**

**与旧版本的区别**：
- 旧版本：直接调用 `_hit_zone.enter_block()`
- 新版本：发送 `rhythm:block_reached_zone` 事件，由 RhythmAxisModule 协调调用

```gdscript
# 新版本：只发事件，不直接调用
func update(current_time: float) -> void:
    for block in _sliding_blocks:
        var reached: bool = block.update_progress(current_time)
        if reached:
            # 通过事件通知，不再直接调用 HitZone
            EventBus.fire("rhythm:block_reached_zone", _block_data_from(block))
    
    # Miss 检查也通过事件通知
    EventBus.fire("rhythm:check_miss", {"current_time": current_time})
```

**公共接口**：
```gdscript
func set_extend_params(hit_zone_x: float, extend_distance: float) -> void  # 设置参数
func clear_blocks() -> void                                               # 清理所有块
func add_block(block_data: Dictionary) -> void                            # 添加块
func get_sliding_blocks() -> Array[Dictionary]                            # 获取滑动中的块
func mark_block_judged(block_id: String) -> void                         # 标记块已判定
func update(current_time: float) -> void                                 # 每帧更新
```

### 6. MusicBlock（音乐块）

**职责**：表示单个音乐块的数据和进度计算逻辑（纯数据类）。

**核心属性**：
- `block_id`：唯一标识
- `emit_time`：发射时间
- `hit_target_time`：到达判定区的目标时间
- `slide_duration`：滑动时长
- `_progress`：当前进度[0.0, 1.0]

**核心方法**：
- `update_progress(current_time)`：根据当前时间计算进度，返回是否已到达判定区

```gdscript
func update_progress(current_time: float) -> bool:
    if current_time <= emit_time:
        _progress = 0.0
        return false
    if current_time >= hit_target_time:
        _progress = 1.0
        return true
    _progress = (current_time - emit_time) / slide_duration
    return false
```

**公共接口**：
```gdscript
static func from_data(data: Dictionary) -> RefCounted  # 从数据创建块
func get_progress() -> float                           # 获取当前进度
func update_progress(current_time: float) -> bool    # 更新进度
```

### 7. HitZone（判定区）

**职责**：管理进入判定区的块，处理玩家输入的判定。

**核心功能**：
- 维护`_blocks_in_zone`列表（当前在判定区内的块）
- 根据时间差计算判定结果（Perfect/Good/Miss）
- 发送`rhythm:input_judged`事件
- 自动检测Miss（超时未击打）

**判定窗口**（可通过配置调整）：
- Perfect：±80ms
- Good：±180ms
- Miss：超过300ms

```gdscript
func _judge_delta(delta: float) -> JudgeResult:
    var abs_delta: float = abs(delta)
    if abs_delta <= _judge_perfect_window:
        return JudgeResult.PERFECT
    if abs_delta <= _judge_good_window:
        return JudgeResult.GOOD
    return JudgeResult.MISS
```

**JudgeResult 枚举**：
```gdscript
enum JudgeResult { NONE, PERFECT, GOOD, MISS }
```

**公共接口**：
```gdscript
func set_judge_windows(perfect: float, good: float, miss_after: float) -> void  # 设置判定窗口
func start() -> void                             # 启动
func stop() -> void                              # 停止
func enter_block(block_data: Dictionary) -> void # 块进入判定区
func remove_block(block_id: String) -> void      # 移除块
func judge_input() -> Dictionary                 # 玩家输入判定
func update_miss_check(current_time: float) -> void  # Miss 检查
```

### 8. EffectManager（特效管理器）

**职责**：负责所有视觉动效的创建和播放。

**核心功能**：
- 创建块的视觉节点（ColorRect + glow层）
- 播放发射时的缩放和发光效果
- 播放判定时的特效（Perfect/Good/Miss）
- 显示判定文字
- 管理粒子效果
- 支持滑动时应用发光 Shader

**三种判定的动效**：
- **Perfect**：金色强烈光芒爆发 + 粒子爆发 + "PERFECT"文字
- **Good**：绿色中等光芒 + 粒子爆发 + "GOOD"文字
- **Miss**：灰色暗光 + 抖动效果 + "MISS"文字

**公共接口**：
```gdscript
func set_config(config: RhythmEffectConfig) -> void                           # 设置配置
func get_config() -> RhythmEffectConfig                                      # 获取配置
func create_block_node(block_id: String, config_dict: Dictionary) -> Node    # 创建块节点
func play_emit_effect(block_node: Node, block_id: String) -> void            # 播放发射动效
func update_block_effects(block_id: String, progress: float) -> void        # 更新块动效
func play_judge_effect(block_id: String, result: int, delta: float) -> void  # 播放判定动效
func remove_block(block_id: String) -> void                                  # 移除块
func clear_all_blocks() -> void                                             # 清理所有块
func set_hit_zone_info(hit_zone_x: float, axis_y: float) -> void            # 设置判定区信息
func set_extend_distance(distance: float) -> void                           # 设置扩展距离
func set_block_config(block_size: float, block_color: Color, axis_y: float) -> void  # 设置块配置
```

### 9. 输入策略系统（HitInputStrategy）

**职责**：定义判定输入的接口规范，支持灵活配置单键或多键判定。

#### 9.1 HitInputStrategy（基类）

**核心功能**：
- 抽象接口：定义 `get_required_keys()`、`check_input()`、`get_input_description()`
- 所有输入策略的基类

**公共接口**：
```gdscript
func get_required_keys() -> Array          # 获取需要的按键列表
func check_input() -> bool                # 检查当前输入是否满足条件
func get_input_description() -> String    # 获取按键描述（用于UI显示）
```

#### 9.2 SingleKeyInputStrategy（单键策略）

**职责**：只有按下指定按键时才触发判定。

**核心功能**：
- 支持任意单个按键
- 默认使用空格键（KEY_SPACE）
- 支持 `ui_accept` 动作

**使用示例**：
```gdscript
var strategy = SingleKeyInputStrategy.new(KEY_SPACE)  # 空格键判定
var strategy = SingleKeyInputStrategy.new(KEY_A)       # A键判定
rhythm_module.set_input_strategy(strategy)
```

#### 9.3 MultiKeyInputStrategy（多键策略）

**职责**：需要同时按下所有指定按键时才触发判定。

**核心功能**：
- 支持多个按键组合
- 必须同时按下所有指定按键才触发判定

**使用示例**：
```gdscript
var strategy = MultiKeyInputStrategy.new([KEY_A, KEY_S])  # A + S 同时按下
rhythm_module.set_input_strategy(strategy)
```

#### 9.4 RhythmAxisModule 中的输入策略管理

**新增接口**：
```gdscript
func set_input_strategy(strategy: RefCounted) -> void    # 设置通用输入策略
func get_input_strategy() -> RefCounted                   # 获取当前输入策略
func set_single_key_input(key_code: int) -> void        # 设置单键判定
func set_multi_key_input(key_codes: Array) -> void      # 设置多键判定
```

## 二、数据流转方向

完整的核心流程如下：

```
BeatGenerator (定时触发)
        │
        ▼ 发送 "rhythm:beat"
RhythmEmitter (创建块数据)
        │
        ▼ 发送 "rhythm:block_emitted"
RhythmAxisModule (接收事件)
        │
        ├──► RhythmAxisLogic.add_block() ──► MusicBlock (数据)
        │
        └──► EffectManager.create_block_node() ──► 可视化节点
                │
                ▼
每帧更新：RhythmAxisLogic.update() ──► 计算进度
                │
                ▼ 发送 "rhythm:block_reached_zone"
RhythmAxisModule (协调者，监听事件)
                │
                ▼ 调用 _hit_zone.enter_block()
HitZone (判定逻辑)
                │
                ▼
玩家输入：HitZone.judge_input() ──► 判定逻辑
                │
                ▼ 发送 "rhythm:input_judged"
RhythmAxisModule + EffectManager
                │
                ├──► 播放判定特效
                │
                └──► 移除块数据
```

**关键改进**：RhythmAxisLogic 不再直接调用 HitZone，而是通过事件通知 RhythmAxisModule，由协调者决定如何处理。

## 三、EventBus 事件使用

### 发送的事件

| 事件名 | 发送者 | 数据内容 |
|--------|--------|----------|
| `rhythm:beat` | BeatGenerator | `{beat_type, intensity, beat_number, beat_in_measure}` |
| `rhythm:block_emitted` | RhythmEmitter | `{block_id, emit_time, hit_target_time, slide_duration}` |
| `rhythm:block_reached_zone` | RhythmAxisLogic | `{block_id, emit_time, hit_target_time, slide_duration}` |
| `rhythm:check_miss` | RhythmAxisLogic | `{current_time}` |
| `rhythm:input_judged` | HitZone | `{block_id, result, delta}` |
| `rhythm:input_requested` | 外部（测试场景等） | `{}` |

### 监听的事件（RhythmAxisModule）

```gdscript
func _subscribe_events() -> void:
    EventBus.listen("rhythm:block_emitted", self, "_on_block_emitted")
    EventBus.listen("rhythm:beat", self, "_on_beat")
    EventBus.listen("rhythm:input_requested", self, "_on_input_requested")
    EventBus.listen("rhythm:input_judged", self, "_on_input_judged")
    # 新增：块到达判定区事件
    EventBus.listen("rhythm:block_reached_zone", self, "_on_block_reached_zone")
    # 新增：Miss 检查事件
    EventBus.listen("rhythm:check_miss", self, "_on_check_miss")
```

### 事件处理流程

1. **`rhythm:beat`** → `_on_beat()` → 调用`_emitter.emit_block()`
2. **`rhythm:block_emitted`** → `_on_block_emitted()` → 创建块数据和可视化节点
3. **`rhythm:block_reached_zone`** → `_on_block_reached_zone()` → 调用`_hit_zone.enter_block()`
4. **`rhythm:check_miss`** → `_on_check_miss()` → 调用`_hit_zone.update_miss_check()`
5. **`rhythm:input_requested`** → `_on_input_requested()` → 调用`_hit_zone.judge_input()`
6. **`rhythm:input_judged`** → `_on_input_judged()` → 播放判定特效

## 四、模块依赖关系

```
RhythmAxisModule (主模块/协调者)
    │
    ├──► BeatGenerator ──► BeatStrategy (线性策略)
    │
    ├──► RhythmEmitter (无依赖)
    │
    ├──► RhythmAxisLogic ──► MusicBlock
    │           │
    │           └──► (不再直接依赖 HitZone，通过事件通知)
    │
    ├──► HitZone (RefCounted)
    │       │
    │       └──► HitInputStrategy (输入策略)
    │           │
    │           ├──► SingleKeyInputStrategy (单键策略)
    │           │
    │           └──► MultiKeyInputStrategy (多键策略)
    │
    └──► EffectManager (Node)
```

**依赖方向**：
- 主模块依赖所有子组件
- RhythmAxisLogic **不再依赖 HitZone**，改为通过 EventBus 事件通知
- BeatGenerator 依赖 BeatStrategy（策略模式）
- HitZone 依赖 HitInputStrategy（策略模式）
- EffectManager 独立，仅处理视觉
- **RhythmAxisModule 作为协调者，监听事件并调用 HitZone**

**架构改进点**：
- 旧版本：RhythmAxisLogic → HitZone（直接耦合）
- 新版本：RhythmAxisLogic → EventBus → RhythmAxisModule → HitZone（解耦）
- 输入策略：HitZone → HitInputStrategy（策略模式，支持单键/多键）

## 五、关键算法逻辑

### 1. 进度计算算法

块的X位置根据进度线性插值计算：

```gdscript
var progress: float = (current_time - emit_time) / slide_duration
progress = clamp(progress, 0.0, 1.0)
var x_pos: float = progress * _config["hit_zone_x"]
```

- 进度 = (当前时间 - 发射时间) / 滑动时长
- X坐标 = 进度 × 判定区X位置

### 2. 判定时间窗口算法

```gdscript
func _judge_delta(delta: float) -> JudgeResult:
    var abs_delta: float = abs(delta)
    if abs_delta <= _judge_perfect_window:      # 80ms
        return JudgeResult.PERFECT
    if abs_delta <= _judge_good_window:         # 180ms
        return JudgeResult.GOOD
    return JudgeResult.MISS                      # >180ms 或负向过大
```

### 3. Miss自动检测算法

```gdscript
func update_miss_check(current_time: float) -> void:
    for entry in _blocks_in_zone:
        var b: Dictionary = entry.block_data
        var hit_target: float = b.get("hit_target_time", 0.0)
        if current_time > hit_target + _judge_miss_after:  # 300ms超时
            _fire_judge(bid, JudgeResult.MISS, current_time - hit_target)
```

        ┌──────────────────────────────────────────────┐

**架构说明**：
- RhythmAxisModule 作为**协调者**，监听所有事件并协调各模块
- RhythmAxisLogic 只负责数据调度，**不直接调用** HitZone
- HitZone 的调用权交给 RhythmAxisModule，实现了完全的解耦
- **HitInputStrategy** 提供灵活的输入判定策略，支持单键/多键模式

## 总结

这是一个典型的**观察者模式 + 数据驱动 + 事件解耦 + 策略模式**的游戏系统：

1. **BeatGenerator** 作为心脏，按固定BPM跳动
2. **EventBus** 作为消息中枢，解耦各模块
3. **RhythmAxisLogic** 作为数据核心，只负责块的生命周期管理，通过事件通知
4. **RhythmAxisModule** 作为协调者，监听事件并决定如何处理（可以替换判定逻辑）
5. **HitZone** 负责游戏性（判定逻辑），不直接被 RhythmAxisLogic 依赖
6. **EffectManager** 负责表现层（视觉动效）
7. **HitInputStrategy** 负责输入判定（策略模式），支持单键/多键灵活配置

### 架构优势

- **高内聚**：每个模块只做一件事
- **低耦合**：RhythmAxisLogic 不再直接依赖 HitZone
- **易扩展**：如果要替换判定模式（如音游模式、卡牌模式），只需修改 RhythmAxisModule 的事件处理逻辑
- **可测试**：各模块可以通过 EventBus 独立测试
- **灵活的输入策略**：通过 HitInputStrategy 策略模式，支持单键/多键判定，可轻松扩展更多输入模式

### 事件驱动流程

```
RhythmAxisLogic (数据调度) ──事件──► RhythmAxisModule (协调者) ──调用──► HitZone (判定)
                                                                              │
                                                                              ▼
                                                                        HitInputStrategy
                                                                   (单键/多键策略)
```

整个系统设计清晰，职责分离明确，易于扩展。
