# 节奏牌 - 游戏设计文档

## 🎮 游戏概述

**节奏牌**是一款融合 **Roguelike 线性探索** 与 **节奏对战** 的回合制卡牌构筑游戏。

### 游戏内容设计
- **局外**：线性 Roguelike 探索，随机事件、战斗、奖励
- **局内**：节奏卡牌对战，魔法吟唱、节奏判定、策略博弈
---

## 📖 游戏流程

```
主菜单
  ↓
开始冒险（局外）
  ↓
[探索循环] → 随机事件 → 获得卡牌/机制/奖励
  ↓           ↓
  ↓        遭遇战斗
  ↓           ↓
  ↓      [节奏卡牌对战]（局内）
  ↓           ↓
  ↓        战斗结算
  ↓           ↓
  └←←←←←←←←←←┘
  ↓
推进进度 → 通关/失败
```

## 🗺️ 局外系统：Roguelike 探索

### 核心机制
玩家控制角色在线性路线上前进，遭遇各种随机节点：

#### 节点类型
- **战斗节点**：进入节奏卡牌对战
- **事件节点**：随机事件（选择分支、获得奖励/惩罚）
- **商店节点**：购买卡牌、移除卡牌、购买遗物
- **休息节点**：恢复生命值、升级卡牌
- **精英战斗**：高难度战斗，丰厚奖励
- **Boss 战**：关卡 Boss，通关后进入下一章

### 进度推进
- 每次完成节点后，玩家选择下一个节点
- 逐步推进至关卡终点（Boss 战）
- 战败则冒险结束（Roguelike 永久死亡）

### 成长系统
- **获得卡牌**：战斗后选择新卡牌加入卡组
- **获得遗物**：永久被动效果（如"每回合多抽1张牌"）
- **升级卡牌**：在休息点强化现有卡牌
- **移除卡牌**：在商店移除弱卡，精简卡组
- **获得机制**：战斗后选择新机制加入卡组

## ⚔️ 局内系统：节奏卡牌对战

### 对战设定
两名魔法师进行法术决斗，通过吟唱咒语释放法术攻击对手。

### 回合流程

#### 1. 预备阶段
**玩家操作**：
- 从手牌中选择本回合要释放的法术
- 每张法术卡有**费用**限制（如总费用 3，可选 1+2 或 3 张 1 费卡）
- 确认后进入吟唱阶段

**卡牌类型**：
- **攻击牌**：造成伤害
- **防御牌**：获得护盾
- **增益牌**：临时 Buff（如"下次攻击+2"）
- **减益牌**：给对手 Debuff（如"下回合费用-1"）
- **特殊牌**：独特机制（如"抽牌"、"回复"）

#### 2. 吟唱阶段（核心玩法）
**节奏机制**：
- 游戏生成**固定节拍**（如 BPM 120，每 0.5 秒一拍）
- 玩家**只能在节拍点**进行操作
- **跳拍或落拍**会导致卡壳（暂停 1 拍）

**玩家操作**：
1. **选择咒语**：在节拍点选择要吟唱的法术（选定后锁定）
2. **吟唱输入**：
   - 每张法术有**固定吟唱序列**（如 "ASDF" 或 "QWER"）
   - 玩家在节拍点按顺序输入字符
   - 输入正确则吟唱进度+1，输入错误则卡壳
3. **扰乱对手**：
   - 在节拍点输入**额外咒语**（如按下 "X"）
   - 对手的节奏会**加快或变难**（如节拍间隔缩短）
4. **反制扰乱**：
   - 被扰乱方可以**反制**（如在特定时机按 "Z"）
   - 反制成功则扰乱方受到惩罚（节奏变难或停顿）

**吟唱完成**：
- 法术吟唱序列全部输入正确后，法术进入**结算队列**
- 可继续选择下一张法术吟唱

**阶段结束条件**：
- 达到时间限制（如 60 秒）
- 双方都释放完所有选定的法术

#### 3. 结算阶段
**结算规则**：
- 按照**先进先结算**原则（先完成吟唱的法术先结算）
- 依次执行法术效果：
  - 造成伤害
  - 施加/移除 Buff/Debuff
  - 触发特殊效果

**胜负判定**：
- 任一玩家生命值归零 → 对手胜利
- 特殊机制达成（如"集齐 5 个符文"）

## 📊 项目架构

### 技术栈
- **引擎**：Godot 4.x
- **语言**：GDScript
- **架构**：模块化 + 事件驱动

### 核心系统
```
节奏牌/
├── core/                    # 核心系统
│   ├── GameCore.gd         # 模块管理器
│   ├── EventBus.gd         # 事件总线
│   └── managers/           # 核心管理器
│
├── modules/                # 功能模块
│   ├── run/                # 局外系统
│   ├── battle/             # 局内系统
│   └── cards/              # 卡牌系统
│
├── data/                   # 游戏数据
│   ├── cards/             # 卡牌数据库
│   ├── characters/           # 敌人数据库
│   ├── events/            # 事件数据库
│
└── scenes/                # 场景
	├── main/              # 主菜单
	├── run/               # Run 主场景
	└── battle/            # 战斗场景
```

## 📝 设计原则

### 1. 模块独立性
- 每个系统独立开发、测试
- 通过事件总线通信，避免强耦合

### 2. 数据驱动
- 卡牌、敌人、事件数据化配置
- 易于扩展新内容
