# 节奏牌 - 开发指南

## 🎯 架构概述

### 核心设计理念
- **模块化**：功能独立，易于扩展
- **事件驱动**：模块间通过事件总线通信
- **数据驱动**：配置与逻辑分离

### 架构组成
```
GameCore（模块管理器）
	↓
EventBus（事件总线）← → 各功能模块
	↓
Managers（核心管理器）
```

## 📦 模块开发规范

### 模块生命周期

所有模块必须继承 `BaseModule` 并实现以下接口：

```gdscript
extends Node
class_name BaseModule

func initialize() -> void:
	"""初始化：加载配置、订阅事件"""
	pass

func start() -> void:
	"""启动：开始运行逻辑"""
	pass

func stop() -> void:
	"""停止：暂停运行"""
	pass

func cleanup() -> void:
	"""清理：释放资源、取消订阅"""
	pass
```

### 模块模板

```gdscript
extends BaseModule
## [模块名称] - [功能描述]

# ========== 配置 ==========
const CONFIG_PATH = "res://data/configs/your_config.tres"

# ========== 状态 ==========
var _is_initialized: bool = false
var _is_running: bool = false

# ========== 生命周期 ==========

func initialize() -> void:
	if _is_initialized:
		return
	
	_load_config()
	_setup_components()
	_subscribe_events()
	
	_is_initialized = true
	print("[YourModule] 初始化完成")

func start() -> void:
	if not _is_initialized:
		push_error("[YourModule] 未初始化")
		return
	
	_is_running = true
	print("[YourModule] 启动")

func stop() -> void:
	_is_running = false

func cleanup() -> void:
	_unsubscribe_events()
	_is_initialized = false

# ========== 私有方法 ==========

func _load_config() -> void:
	# 加载配置文件
	pass

func _setup_components() -> void:
	# 初始化组件
	pass

func _subscribe_events() -> void:
	# 订阅事件
	EventBus.listen("event_name", self, "_on_event")

func _unsubscribe_events() -> void:
	# 取消订阅
	EventBus.unlisten("event_name", self)

# ========== 公共接口 ==========

func your_public_method() -> void:
	"""对外提供的方法"""
	if not _is_running:
		return
	# 实现逻辑

# ========== 事件处理 ==========

func _on_event(data) -> void:
	"""事件回调"""
	pass
```

## 🔄 事件通信规范

### 事件命名规则
```
模块名:动作_对象
```

### 常用事件类别

**Run 系统**：
- `run:started` - Run 开始
- `run:node_selected` - 选择节点
- `run:floor_advanced` - 进入下一层
- `run:ended` - Run 结束

**战斗系统**：
- `battle:started` - 战斗开始
- `battle:phase_changed` - 阶段切换
- `battle:turn_start` - 回合开始
- `battle:damage_dealt` - 造成伤害
- `battle:ended` - 战斗结束

**卡牌系统**：
- `card:drawn` - 抽牌
- `card:played` - 打出卡牌
- `card:discarded` - 弃牌
- `card:effect_triggered` - 效果触发

**节奏系统**：
- `rhythm:beat` - 节拍触发
- `rhythm:input_judged` - 输入判定
- `rhythm:spell_completed` - 咒语完成

### 发送事件

```gdscript
# 简单事件
EventBus.fire("battle:started")

# 带数据的事件
EventBus.fire("card:played", {
	"card_id": "fireball",
	"player_id": 1,
	"cost": 2
})
```

### 监听事件

```gdscript
func initialize() -> void:
	EventBus.listen("card:played", self, "_on_card_played")

func _on_card_played(data: Dictionary) -> void:
	var card_id = data.card_id
	var cost = data.cost
	# 处理逻辑
```

## 📁 文件组织规范

### 模块文件结构

```
modules/your_module/
├── YourModule.gd          # 模块主文件
├── scenes/                # 场景文件
│   ├── main_scene.tscn
│   ├── main_scene.gd      # 场景脚本（与 .tscn 同名）
│   └── sub_scene.tscn
├── scripts/               # 辅助脚本
│   ├── component_a.gd
│   └── component_b.gd
└── resources/             # 模块资源
	├── sprites/
	├── audio/
	└── data/
```

### 命名规范

**文件命名**：
- 脚本：`snake_case.gd`（如 `rhythm_judge.gd`）
- 场景：`snake_case.tscn`（如 `card_hand.tscn`）
- 资源：`snake_case.tres`（如 `fireball_card.tres`）

**代码命名**：
- 类名：`PascalCase`（如 `RhythmModule`）
- 变量/函数：`snake_case`（如 `current_hp`）
- 常量：`UPPER_SNAKE_CASE`（如 `MAX_HAND_SIZE`）
- 私有成员：`_snake_case`（如 `_is_running`）

## 🧪 测试场景

### 创建测试场景

每个模块都应该有独立的测试场景：

```
scenes/test_scenes/test_your_module.tscn
```

### 测试场景模板

```gdscript
extends Node
## [模块名称] 测试场景

@onready var module = GameCore.get_module("YourModule")

func _ready() -> void:
	print("=== 测试 YourModule ===")
	_test_basic_functionality()
	_test_events()

func _test_basic_functionality() -> void:
	print("测试基础功能...")
	module.your_public_method()
	print("✓ 基础功能正常")

func _test_events() -> void:
	print("测试事件通信...")
	EventBus.listen("your_module:test_event", self, "_on_test_event")
	EventBus.fire("your_module:test_event", "test_data")

func _on_test_event(data) -> void:
	print("✓ 事件接收成功: ", data)

func _input(event: InputEvent) -> void:
	if event.is_action_pressed("ui_accept"):  # Space
		print("手动触发测试...")
		_test_basic_functionality()
	
	if event.is_action_pressed("ui_cancel"):  # Esc
		get_tree().reload_current_scene()
```

## 👥 团队协作流程

### 1. 开始新功能

```bash
# 1. 从主分支创建功能分支
git checkout main
git pull origin main
git checkout -b feature/your-feature-name

# 2. 创建模块文件夹
mkdir -p modules/your_module/{scenes,scripts,resources}

# 3. 开始开发
```

### 2. 开发规范

**✅ 推荐做法**：
```gdscript
# 通过事件总线通信
EventBus.fire("card:played", card_data)
```

**❌ 避免做法**：
```gdscript
# 直接调用其他模块（强耦合）
var combat_module = GameCore.get_module("Combat")
combat_module.apply_damage(10)
```

### 3. 提交代码

```bash
# 1. 检查修改
git status

# 2. 添加文件
git add modules/your_module/

# 3. 提交（使用规范的提交信息）
git commit -m "feat: 实现 YourModule 基础功能"

# 4. 推送到远程
git push origin feature/your-feature-name
```

### 提交信息规范

```
类型: 简短描述

详细描述（可选）

类型：
- feat: 新功能
- fix: 修复 bug
- docs: 文档更新
- style: 代码格式调整
- refactor: 重构
- test: 测试相关
- chore: 构建/工具相关
```

示例：
```
feat: 实现节奏判定系统

- 添加节拍生成器
- 实现输入判定逻辑
- 添加 Perfect/Good/Miss 判定
```

## 🚨 常见问题

### Q1: 如何访问其他模块的功能？

**A**: 通过事件总线通信，不要直接调用。

```gdscript
# ❌ 错误做法
var card_module = GameCore.get_module("Card")
card_module.draw_card()

# ✅ 正确做法
EventBus.fire("card:request_draw")
```

### Q2: 模块初始化顺序重要吗？

**A**: 不重要。使用事件总线通信可以避免初始化顺序依赖。

### Q3: 如何在模块间共享数据？

**A**: 通过事件传递数据，或使用共享的 Resource 数据文件。

```gdscript
# 方式1: 事件传递
EventBus.fire("data:updated", {
	"score": 100,
	"level": 5
})

# 方式2: 共享 Resource
var game_data = load("res://data/configs/game_data.tres")
```

### Q4: 如何处理模块间的复杂交互？

**A**: 创建专门的协调模块（如 `BattleModule`）来处理复杂流程。

## 📊 模块分工建议

### 核心系统（架构负责人）
- `GameCore.gd` - 模块管理
- `EventBus.gd` - 事件总线
- `RunManager.gd` - Run 状态管理
- `SceneTransition.gd` - 场景切换

### 局外系统（成员 A）
- `modules/run/map/` - 地图生成
- `modules/run/events/` - 随机事件
- `modules/run/shop/` - 商店系统
- `modules/run/rewards/` - 奖励系统

### 局内系统（成员 B）
- `modules/battle/combat/` - 战斗逻辑
- `modules/battle/rhythm/` - 节奏判定
- `modules/battle/workbench/` - 工作台系统
- `modules/battle/duelists/` - 决斗者系统

### 卡牌系统（成员 C）
- `modules/cards/` - 卡牌模块
- `data/cards/` - 卡牌数据
- 卡牌效果实现

**核心原则**：
- **保持模块独立**：每个模块可独立开发、测试
- **使用事件通信**：避免模块间强耦合
- **频繁测试**：每次修改后运行测试场景
- **及时提交**：小步快跑，频繁提交代码
